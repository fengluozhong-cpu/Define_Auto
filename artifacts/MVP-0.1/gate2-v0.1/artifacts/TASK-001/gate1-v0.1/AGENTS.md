## 2. 不得偏移的产品目标

长期产品是 **Define-XML 2.1 + SDRG/ADRG 自动化系统**。以 Metadata Reconciliation 为核心，汇聚 XPT、SDTM/ADaM Spec、aCRF／采集预设值、CT、Protocol、SAP、项目问题与决策记录，形成带决策与溯源的 DDS-aligned 中心模型，再生成、验证和供人批准。

阶段缩小只限制当前实现，不能删除长期的 ADaM、Protocol/SAP、No Data、VLM、SUPP、CodeList、RG 或验证能力。只做 XPT 扫描器、P21 包装器、校验器或文档写作器，均不足以替代完整目标。

## 4. 变更控制

文件职责：GOALS 管长期目标；REQUIREMENTS 管需求与证据；ARCHITECTURE 管技术边界与设计决策；PLANS 管当前状态／任务索引、阶段、批准及通用验收规则；`docs/tasks/` 管实际任务卡、执行证据及历史交接。本文件只维护工作规则，不重复保存业务事实。规范正文只有一个主位置，其他文件引用；G／FR／NFR／AC／OQ／ADR／CTRL／Task／Change ID 移动不重编号，废止不复用，替代保留关联和迁移索引。

每项变更依次执行：

1. 读取最新文件与已有改动，定位需求 ID／决策 ID，记录变更原因与影响。
2. 普通实现细节在已批准范围内自行判断。涉及长期目标、阶段范围、中心模型契约、来源权威、关键语义、数据外发、核心依赖或外部状态的变化，先提出具体变更并等待对应批准；可继续独立工作。
3. 在 PLANS 的变更表记录 `change_id、提出日期、原因、影响需求／决策、批准人、批准时间、状态`。沉默、助手建议和旧文档的“已锁定”不能替代 Chris 对本项目的批准。
4. 按最小范围编辑，更新受影响文档及必要检查；写入前发现文件变化则重读合并，不覆盖其他任务成果。
5. 按 PLANS 的 CTRL-01 任务卡和 CTRL-02 质量门判定完成，记录实际证据、未决项及审阅结果，再更新交接表。明确区分“修改及检查完成”“任务／阶段验收完成”“批准交付”，未批准的提案保留为 DRAFT。

修正事实可以基于新证据提出，但必须保留原结论、纠正理由和影响；不能静默把不确定信息升级为事实。批准与冻结按 PLANS 的 CTRL-03 保存可恢复快照，后续修订不得覆盖批准对象。
