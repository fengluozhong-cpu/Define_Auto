## 1. 产品目标

构建面向统计编程人员的 Define-XML 2.1 与 SDRG／ADRG 自动化系统，减少跨文件核对、元数据填表与重复撰写，并使结果可检查、可纠正、可重跑、可追溯。人的工作集中在冲突裁决、复杂衍生、医学／统计解释与最终批准。

中心能力是 **Metadata Reconciliation**：区分“项目设计要求什么”“实际数据包含什么”“适用标准允许什么”“人最终决定什么”，解释差异，并让同一份经审阅的元数据支持 Define 与 RG。

## 3. 目标不变量

- 观察到的值不等于允许／预设值全集。不能因未观察到某 term、VLM 条件、变量或域，就静默删除设计元数据。
- No Data 必须结合完整输入范围、预期对象和人工解释判断；缺文件、读失败、未提供和确实无数据必须分开。
- 共享中心模型保留候选、冲突和来源。生成器消费已核对的快照，不能各自重新猜测项目事实。
- 标准信息提供约束和参考；Spec、aCRF、Protocol、SAP 也可能冲突，不能用固定的“后读覆盖先读”规则消灭冲突。
- 自动化结果始终可审阅；最终业务和提交批准由有权限的人负责。未批准的 LLM 输出不成为权威事实。
- 随着 MVP 推进，G-01 至 G-08 继续保留。延期需要记录原因和回归条件，不能改写成永久非目标。

## 4. 当前范围与长期范围

**Task 000 已完成**：五份项目基线已获批准；资料与证据分层、后续阶段及批准门已建立。不代表系统代码已实现。

**建议首个实现范围**：经批准后，以少量公开／合成 SDTM XPT + 结构化 Spec 建立核对闭环，并预留中心模型、决策与溯源契约；先证明差异能正确发现和裁决，再扩展生成器。该方向已随基线批准；具体任务执行、样本和业务预期仍按阶段门确认。

**后续保留**：aCRF 预设值、CT、VLM／SUPP／No Data，P21 与直接 XML 适配器比较，SDRG、ADaM／ADRG、Protocol／SAP／USDM、增量影响分析及生产验证。

**当前不承诺**：替代完整 P21 Enterprise、所有研究全自动生成、固定节省百分比、自动合规批准、直接处理生产数据、自动生成完整 SDTM／ADaM 分析程序。ARM（Analysis Results Metadata）是候选扩展，须单独确定需求，不与 Trial Arms 混淆。SEND、门户看板和多用户平台暂不纳入实现范围。

## 5. 如何衡量成功

| 维度 | 观察方式 | 当前约束 |
|---|---|---|
| 正确性 | 与人工批准的预期结果比对，统计漏报、误报和错误自动裁决 | 不设未经样本验证的准确率承诺；关键夹具的明确预期必须全部满足 |
| 完整性 | 每个计划对象均有状态；预设 term／空 VLM 等不会因数据缺席而遗失 | 输入不完整时明确报告，不宣称完整覆盖 |
| 可追溯性 | 抽查任一输出字段及 RG 结论能定位原文件／版本／位置、变换及批准 | 发布范围内所有关键字段须可追溯；范围清单由 Chris 批准 |
| 可重现性 | 相同输入、规则、标准及批准快照重复运行，业务内容和稳定标识相同 | 运行时间等易变审计字段单列；LLM 候选需冻结后才进入确定性链路 |
| 效率 | 在明确大小、复杂度与人工范围的样本上记录基线工时及审阅工时 | 不将其他团队的自动化率或节省工时当作本项目证据 |
| 可维护性 | 换标准版本、模板或生成器时能看见影响并验证回归 | 不要求先建数据库、服务或通用平台 |
